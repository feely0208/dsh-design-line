# 深鲸工序（设计工序流水线）

给设计师做「工序优化」：把一条**完整的活**一口气跑完，而不是零散小操作。
一个包 = 一份内核 + 三个适配器（PS / AutoCAD / 3ds Max）。

CLI：`<cli 路径>`

## 什么时候用

用户说这些话的时候：
- 「把这批图出成交付」「统一尺寸加水印」「按客户要的几个尺寸出一套」「出个交付清单」
- 「这批图纸规范化」「按标准套图框」「批量出 PDF」「出图纸目录」
- 「把这些场景批量渲了」「套材质灯光」「按机位出图」
- 「帮我批量改图/批量导出/批量出图」这类**围着交付转的杂活**

## 三条规矩（必须先做）

1. **先 plan 落盘给用户看，再 run。** 不许直接开跑 —— 用户要能先看到「分几步、每步干什么、失败怎么回退」。
2. **判据在产物那边。** 跑完不看脚本自报，看 `回执.md` 与 `交付清单.csv`。
3. **改图不可逆的事，没有备份不动手。** CAD / Max 一律先备份；备份不成功就停。

## 怎么跑

```bash
CLI="<cli 路径>"

# 0) 本机有没有宿主（PS / AutoCAD / 3ds Max）
"$CLI" detect photoshop

# 1) 看内置流水线（三条）
"$CLI" 流水线

# 2) 写一份意图（用户的参数），先落盘审阅 —— 不执行
"$CLI" plan 流水线/ps-出图交付.json --intent 意图.json --out 运行-ps
#    产出：脚本/（可读可改）、计划.json（每步做什么/调什么接口/怎么验证/失败怎么回退）、状态.json

# 3) 让用户确认后再执行
"$CLI" run 运行-ps
"$CLI" run 运行-ps --步骤 S5      # 只补某一步
"$CLI" run 运行-ps --重跑          # 重跑已完成的

# 4) 复核 + 给客户的凭证
"$CLI" verify 运行-ps             # 独立校验（重算指纹、核对是不是本次生成）
#    回执.md 在运行目录里，可以直接给客户
```

## 三条流水线

| 流水线 | 干什么 | 替掉多少 |
|---|---|---|
| `流水线/ps-出图交付.json` | 收料 → 规范命名 → 统一尺寸 → 水印版权 → 按规格导出 → 交付清单 | 半天 |
| `流水线/cad-出图标准化.json` | 图纸台账 → 备份+图层规范化 → 图框比例 → 标注文字样式 → 打印样式 → 批量出图 → 图纸目录 | 一天 |
| `流水线/max-批渲染交付.json` | 场景台账 → 规范检查 → 材质灯光套用 → 渲染参数 → 批量渲染（可续跑）→ 归档 → 清单 | 一天 |

## 边界（不许越）

- **文件数上限**：PS 默认 500 张、CAD 200 张/CAD 会要确认、Max 20 个场景会要确认 —— 超了先问用户是不是选错目录
- **日志与磁盘**：内核日志上限 8MB；跑前磁盘 < 1GB 拒绝开跑
- **不联网**：全程本机，素材不出门（脚本里没有任何联网写法）
- 交付目录与过程痕迹分开：`交付包/` 是给客户的，`_运行日志.txt` / `异常.md` 是给设计师的

## 不装 DSH 也能用（另一条腿）

同一套流水线可以导出成**双击就跑**的脚本给设计师：
PS → `.jsx`（在 PS 里走 文件 > 脚本 > 浏览）；CAD → `一键出图.bat`；Max → `批渲染.bat`。
生成方式见「测试包」工具。
